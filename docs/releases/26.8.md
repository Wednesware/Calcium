# Calcium 26.8 — Bonemarrow application foundations

26.8 expands the independent C runtime toward ordinary application code. Supported
features execute in CaRT; there is no automatic CPython fallback. This is a
compatibility expansion, not a claim that all Discribe features now build or that
applications are universally faster than Python.

## Language

- Single-inheritance classes, instances, methods, static/class methods and read-only
  properties; normal instance attributes and `__getattr__`.
- Nested and conditional function definitions, closures, `nonlocal`, lambdas and
  function decorators, including per-definition defaults and captured cells.
- Native exceptions, explicit causes, reraising, `try`/`except`/`else`/`finally`,
  assertions and synchronous context managers.
- List/set/dictionary comprehensions, lazy generator expressions, f-strings and
  assignment expressions. General generator functions and async remain unsupported.
- Bytes, conversions, stable merge sorting with keys/reverse, enumeration, zip,
  dictionary views and additional Unicode/string/bytes methods.
- True/floor division, remainder and powers. Integer division preserves arbitrary
  precision; true division rounds large integer ratios without intermediate float
  overflow, including subnormal boundaries.
- `from __future__ import annotations` is accepted. Annotations do not establish
  unchecked type assumptions; full annotation reflection/evaluation is not provided.

## Native libraries

Selected APIs now have C implementations in `pathlib`, `os`/`os.path`, `tempfile`,
`shutil`, `json`, `hashlib`, `sqlite3`, `datetime`, `uuid`, `secrets`, `time`,
`dataclasses` and `functools`. These are bounded API subsets, not replacements for
all of those modules. See [the supported API contract](../NATIVE_LIBRARIES.md).

SHA-256 uses OpenSSL and persistence uses SQLite's C API. Compiling those mature
libraries' Python wrappers would add work without accelerating the native engines.
They are linked only when imported; their builds require `pkg-config` and the
corresponding development packages. Other library operations execute directly in
CaRT. Generated executables still require no interpreter, Python headers or
libpython. Dynamically linked OpenSSL/SQLite remain deployment dependencies.

## Discribe evidence and limits

A local integration probe imports the unmodified `discribe.core`, saves and loads
documents, checks conflicting revisions, round-trips settings, performs atomic
file writes and checks content digests. With controlled clock/UUID inputs, native
stdout matches CPython. This validates that core workflow, not the complete app.
[Raw results](../benchmarks/discribe-core-26.8.json),
[remaining diagnostics](../benchmarks/discribe-26.8-blockers.json), and the
[probe source](../../examples/native/discribe_core_probe.py) are included.

The complete package still fails explicit native checks: async collaboration,
`argparse`, `contextlib`, `http.server`, and external GUI/web/collaboration packages
need further implementation. `--cpython` remains the compatibility option for the
whole application. Unsupported bodies are not replaced by stubs.

## Runtime and validation

CaRT ABI advances to **3**, with a separate native object-cache namespace. The
tracer now follows classes, instances, closure cells, exception edges, suspended
generator-expression frames and native resource wrappers. Files, directories,
hash contexts and SQLite statements are released at collection/shutdown. SQLite
operations collect discarded cursors before acquiring new locks.

Generated exception landing pads clear register arrays in bulk, avoiding excessive
generated C and compilation cost. Sorting is stable merge sort; dictionary/set
lookup is still linear. Unicode case tables use Unicode 16 data. No end-to-end
speedup is asserted without an application benchmark.
