Calcium 26.2 adds package and whole-project transpilation.

Each discovered project Python source is analyzed and lowered independently into
its own C translation unit. The generated module registry links those units and
executes local imports through their C entry points, including package initializers,
relative imports and valid circular imports. Native project executables and package
extensions can run without the original Python source tree.

```sh
ca transpile path/to/package --output build/c --emit-ir
ca build --module my_package --project-root ./src --output build/myapp
ca build project/main.py --include-all --output build/myapp
```

Projects require native lowering by default: unsupported files produce located
errors instead of silently embedding Python. `--allow-fallback` explicitly enables
reported per-module compatibility fallback. Use `--include-path` for additional
pure-Python source roots and a directory input or `--include-all` for dynamically
selected local modules.

The release includes a wheel, source distribution and SHA-256 checksums. Both
`ca` and `calcium` console commands are installed. Validation covers CPython
3.12–3.14, GCC/Clang, generated artifacts, source-free project execution, package
extensions and import lifecycle behavior.

Calcium still requires compatible CPython and its standard library. Standard-library
modules, binary extensions and undeclared external dependencies remain runtime
imports. Package resources are not bundled. This release adds project compilation;
it does not claim full Python-language lowering or standalone interpreter-free
executables. See `docs/PACKAGES.md` and `docs/IMPLEMENTATION.md` in the repository
for the exact support boundary.
