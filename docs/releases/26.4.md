# Calcium 26.4

Calcium 26.4 keeps eligible integer computations in native C variables, expands
native Python syntax support, and adds relocatable CPython bundles. New function
benchmarks separate computation from interpreter startup and imports.

## Checked unboxed integer kernels

At **O2 and O3**, eligible pure-integer functions use checked C `long` locals and
arithmetic throughout range/while loops. Guarded self-recursion calls the scalar
implementation directly, avoiding repeated Python argument/result boxing inside
the recursive calculation. Values are boxed at the public return boundary;
original parameter/constant objects are retained where return identity requires it.

Exact-type/range and callable guards protect these paths. Overflow, unsupported
arguments or bindings, uninitialized locals and iteration budgets return to the
original generic implementation. Replay is restricted to functions without heap
writes or unknown calls. Arbitrary-precision integers and subclass dispatch remain
available through generic CPython operations. General function specialization,
inlining and unboxed floating-point regions are not included.

## More native language support

The following now lower into native control-flow IR:

- Ordinary `try`/`except`/`else`/`finally`, including handled-exception restoration,
  exception-name cleanup and `return`/`break`/`continue` through pending cleanup.
- Synchronous `with`, including suppression and nested context cleanup.
- List, set and dict comprehensions with private target bindings.
- Dynamic dictionary keys and set expansion.

Exception landing pads and ownership/error edges are verified before C emission.
Context-manager descriptor binding order follows the selected CPython minor,
including the difference between 3.12/3.13 and 3.14.

## Compute benchmarks

```sh
ca examples/compute.py --benchmark --function sum_squares --arguments '[1000000]' -O3 --repeat 9 --warmups 2 --format json
```

`--function` times calls after imports. Type-tagged builtin results, exceptions,
stdout/stderr and private working-directory file contents must agree before
measurements are published. Reports include raw samples, medians, IQR and peak RSS.
RSS covers the entire child process, including imports and validation overhead.
Use `--working-directory PATH` to copy a fixture for each iteration.
The ordinary `--benchmark` continues to measure full process startup and execution.

Local O3 measurements on Linux x86-64, CPython 3.14.8 and GCC 16.2.1, using two
warmups and nine samples per route:

| Workload | Python median | Calcium median | Speedup |
| --- | ---: | ---: | ---: |
| Sum of squares, 1,000,000 integers | 39.764 ms | 1.385 ms | 28.70× |
| Recursive Fibonacci, n=25 | 5.514 ms | 0.944 ms | 5.84× |
| List/dict workload, n=20,000 | 2.081 ms | 1.656 ms | 1.26× |

These are workload-specific observations, not general speed guarantees. Nitrogen
has not been rerun; startup-heavy applications can still be slower than Python.
[Benchmark methodology and raw samples](https://github.com/Wednesware/Calcium/blob/26.4/docs/BENCHMARKS.md)
include reproduction commands and measurement limitations. Filesystem validation
does not sandbox absolute paths, network activity or external side effects.

## Relocatable CPython bundles

```sh
ca my_package/ --bundle -O3 -o dist/myapp
./dist/myapp/run --help
ca main.py --bundle --resource data/ -o dist/script
ca main.py --bundle --no-dependencies -o dist/stdlib-only
```

A bundle includes the compiled executable, matching CPython interpreter/standard
library, the selected environment's installed packages, transitive non-system ELF
libraries and package data. Move the complete directory and launch its `run` file;
a separately installed Python is not required. The output must be a new directory.
`--resource` adds explicit project data, while `--no-dependencies` excludes
site-packages. `Calcium.bundle(...)` exposes the same capability in Python.

Bundles relocate module paths and support `importlib.resources.files(package)`
and data located relative to `__file__`. They still need a compatible Linux C
runtime/ELF loader, architecture and POSIX shell. This is a CPython bundle, not a
CPython-free runtime or a cross-compilation target. See the
[deployment guide](https://github.com/Wednesware/Calcium/blob/26.4/docs/DEPLOYMENT.md)
for resource exclusions and dependency-environment requirements.

## Validation and compatibility

The implementation passed **302 tests per version on CPython 3.12, 3.13 and 3.14**,
with two opt-in UBSan tests run separately using GCC and Clang. The matrix also
passed formatting, wheel/sdist builds and isolated installed-wheel smoke checks.
Bundle tests move outputs to paths containing spaces, remove original sources and
selected dependency environments, and verify imports/resources still work.

Supported native builds remain **Linux, GIL-enabled CPython 3.12–3.14**, with GCC
or Clang, matching development headers and shared libpython. Normal executables
still require host CPython/dependencies unless explicitly built with `--bundle`.

Native classes, closures, decorators/annotations, generators, async, `match` and
`except*` remain subject to reported compatibility execution or strict-mode errors.
Exact Python frames/reflection, broader specialization/inlining, other platforms,
free-threading, subinterpreters and a general C ABI remain open. Scalar kernels
hold the GIL and retain native tracing/scheduling exclusions. The
[remaining-work ledger](https://github.com/Wednesware/Calcium/blob/26.4/docs/STATUS.md)
records these limits.
