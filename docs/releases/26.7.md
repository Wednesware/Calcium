# Calcium 26.7 — Bonemarrow native packages

**Bonemarrow (`bmrw`) is now Calcium's default backend.** It compiles supported
multi-file Python projects into standalone C executables using CaRT, without
CPython, libpython, Python headers, embedded bytecode or runtime importlib.

```sh
ca main.py -O3
ca my_package/ --run
ca --module my_package.cli --project-root ./src
ca main.py --use bmrw -v
ca existing_application/ --cpython
```

This is a breaking default change. Choose `--cpython` for existing applications,
CPython extensions, CPython bundles and broader language/library compatibility.
The Python API likewise defaults to `Calcium(backend="bmrw")`;
`Calcium(backend="cpython", fallback=True)` retains compatibility execution.
Unsupported native features never silently switch runtimes.

## Native projects and imports

- Separate C translation units, isolated module globals and unique symbols.
- Absolute/dotted/relative/aliased imports, from-imports and nested packages.
- Package initializers, `__main__.py`, `--module`, and declared namespace packages.
- Lazy initialization at executed import statements, import caching, partial
  namespaces during circular imports, import errors and cross-module recursion.
- Native module objects/attributes, global references, module metadata and GC roots.
- Standalone binaries continue to run after project sources are removed, with
  empty PATH and invalid Python environment settings.

## Larger native subset

Bonemarrow adds native lists, tuples, dictionaries and sets; indexing, sequence
slicing, iteration, membership and ordinary unpacking; common container methods;
default/keyword-only/variadic parameters and expanded calls. Mutable defaults
retain definition-time evaluation and sharing. Iterative mark/sweep tracing handles
mutable cycles, deep graphs, container buffers and saved bound-method receivers.
Tagged floats preserve NaN identity through copies without numeric heap boxing.

Dictionary/set lookups are currently linear, not optimized hash-table operations.
Cross-module calls execute compiled functions through native tagged dispatch;
cross-module scalar specialization/inlining is still future work. The checked
integer kernels from 26.6 remain available.

## CLI and incremental builds

`--use bmrw`, `--bmrw`, and legacy `--backend native` select Bonemarrow;
`--use cpython`, `--cpython`, and `--backend cpython` select compatibility mode.
Conflicting selections produce a clear configuration error. Normal builds print
artifact paths. `-v`/`--verbose` shows actual optimization, compile/cache reuse and
link stages on stderr. `--fancy` explicitly enables the awakening message.
Generated executables never emit compiler identity/startup messages.

`ca --info` reports Calcium/Bonemarrow versions and available backends. Both
backends use validated content-addressed object caching; native keys fingerprint
compiler/flags/preprocessed headers/CaRT ABI without querying a Python SDK. Every
build relinks; debug/`--no-cache` builds bypass caching.

## Measured reference results

On the recorded Linux/Ryzen/CPython 3.14 run (9 samples, O3), whole-process
median startup was 0.583 ms for a native pass executable versus 9.879 ms for Python.
The 50-module chain took 0.555 ms versus 13.386 ms. The 100,000-cross-module-call
fixture took 7.793 ms versus 19.534 ms. Compilation is measured separately; the
benchmark documentation explains bootstrap/RSS/methodology limitations. These
synthetic results do not establish general application speedups.

## Scope and remaining blockers

Stages A–C and E of the plan are delivered. Language expansion (D) is partial;
validation (F) includes differential tests, GCC/Clang sanitizers, source-free
execution, installed-wheel checks and a three-runtime package benchmark suite.

Classes/instances, structured exceptions, closures/decorators, comprehensions,
standard-library/native-library/GUI bindings and other features remain open.
**Discribe is not natively compatible.** An analysis-only probe of the local
Discribe checkout records located blockers; it was not executed. Native support
remains a documented subset, not a general replacement for CPython.

See [the exact support contract](../NATIVE.md),
[package benchmarks and raw measurements](../NATIVE_BENCHMARKS.md), and
[the Discribe blocker report](../benchmarks/discribe-26.7-blockers.json).

## Distribution

Release assets include the wheel, source distribution, repository ZIP, SHA256SUMS,
and Linux x86_64 native demonstration binaries. The native archive includes
`demo_package`, a multi-file project using imports and containers, plus its
inspectable generated C. Platform C/math libraries and a compatible ELF loader
are still required. The compiler itself requires Python 3.12–3.14.
