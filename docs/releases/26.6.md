# Calcium 26.6 — first standalone native backend

Calcium 26.6 adds an experimental **CPython-independent native backend** with its
own C runtime, CaRT. This is the first working vertical slice of the native-runtime
plan, not complete Python compatibility. **CPython remains the default backend.**

```sh
ca build examples/native/pass.py --backend native -o build/pass
ca examples/native/hello.py --backend native --run
ca examples/native/sum_squares.py --backend native -O3 --run --keep-c
ca build existing_project/ --backend cpython
```

## Independent execution

Native mode generates C11 and links CaRT with the platform C/math libraries. It
does not include Python.h, link libpython, initialize an interpreter, execute
Python source/bytecode, or invoke Python at runtime. Native C emission/building
also avoids target Python SDK queries. The compiler itself remains a Python
application. Initial validation covers Linux LP64 and IEEE binary64.

Unsupported input receives located diagnostics; `--allow-fallback` cannot enable
CPython execution in native mode. Existing compatibility projects, imports,
extensions, fallback and CPython bundles remain available through the default
`--backend cpython`.

## CaRT milestone

- Tagged None/bool/int64/double values without numeric heap boxing.
- Native arbitrary-precision integers with checked promotion for add/subtract/multiply.
- Float arithmetic/formatting and exact mixed int/float comparisons.
- UTF-8 strings, concatenation, repetition, comparison and iteration.
- Variables, if/else, boolean operations, while/range/string loops and loop control.
- Basic module-level functions, positional/named arguments, aliases and recursion.
- print and range builtins, with native error propagation and deterministic cleanup.
- Non-moving tracing memory management with explicit CIR roots, safepoints and
  reclamation of unreachable/shared object graphs.

The backend reuses Calcium's loader/parser, scopes, verified CIR, CFG passes and
pure-integer kernel IR. O2/O3 add checked scalar regions, direct scalar self-recursion
and guarded direct calls between compatible compiled functions. Guard/overflow
misses use generic CaRT, never CPython. Retained C, manifests and native optimization
reports expose specialized/generic functions, dispatch/call sites and potential
allocation sites. Counts are static, not runtime hotness/allocation measurements.

## Measured results

Whole-process medians from a Linux x86-64 Ryzen 5 7600X reference machine, CPython
3.14.8, GCC 16.2.1, O3, two warmups and nine samples per runtime:

| Whole-process workload | Python median | CPython backend | Native backend |
| --- | ---: | ---: | ---: |
| Empty pass | 8.295 ms | 8.803 ms | 0.501 ms |
| Sum of squares, n=1,000,000 | 49.314 ms | 10.604 ms | 2.165 ms |
| Recursive Fibonacci, n=25 | 14.377 ms | 10.418 ms | 1.354 ms |
| String concat/repeat fixture | 10.637 ms | 10.877 ms | 2.693 ms |
| One million compiled calls | 58.947 ms | 118.980 ms | 25.389 ms |

The minimal native executable is 39,128 bytes; measured median child peak RSS is
2.016 MiB, including the measurement helper's small inheritance floor. These are
workload/machine-specific results, not general speed guarantees. Startup is included;
this does not measure GUI editing or sustained string responsiveness.

The [benchmark methodology and raw data](https://github.com/Wednesware/Calcium/blob/26.6/docs/NATIVE_BENCHMARKS.md)
include wall/CPU time, RSS, variation, executable sizes and separate compile times.
Output, status and private-directory file effects are compared before results are
accepted. Unsupported native container/object/import/filesystem categories retain
explicit diagnostics rather than fabricated timings.

## Compatibility limits and validation

Native 26.6 does not implement bytes, mutable containers/tuples, indexing/slicing,
comprehensions, defaults/variadics, classes/attributes/closures/decorators,
generators/async, structured exceptions, imports/packages/standard-library bindings,
or general division/power/bitwise operations. Identity/reflection and Python frame
emulation remain unsupported. Basic primitive signature annotations are accepted
without trusting them as unchecked runtime types. Recursion is limited to 256 calls
and signatures/calls to 128 arguments. Native execution is single-threaded; large
frames use checked heap storage. CPython extensions cannot be loaded into CaRT.

Validation includes real standalone differential binaries at O0–O3, arbitrary
precision and overflow, randomized float formatting/comparisons, Unicode iteration,
rebindings, errors and frame/heap cleanup. GCC and Clang ASan+UBSan tests cover
arithmetic, GC stress and internal cyclic-graph reclamation. Tests remove original
sources, use invalid Python environment paths, check generated sources for Python
APIs and inspect dynamic dependencies for libpython. The full existing CPython
suite remains in place, and installed-wheel smoke tests exercise both backends.

See the [exact native support and ownership contract](https://github.com/Wednesware/Calcium/blob/26.6/docs/NATIVE.md)
for exclusions and next phases. Containers, the object model, native imports and
standard-library/extension ecosystems remain incremental future work. Existing
applications such as Discribe still require the CPython backend.

Release assets contain the 26.6 wheel, source distribution, Nitrogen-compatible
`calcium.zip` and `SHA256SUMS`. Both compiler runtimes' sources are included;
package, CLI and Nitrogen version metadata are aligned at 26.6.
