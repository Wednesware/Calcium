# Calcium 26.9 — native coroutines and application entry points

26.9 removes the reported Discribe C160 blockers: `asyncio`, `contextlib`,
`argparse`, `http.server`, integer bitwise operations, `async def`, `await` and
`async with` now have native implementations. The actual local Discribe package
builds into an executable and its `--help` entry point runs without Python.

This does **not** establish full Discribe runtime compatibility. Nitrogen,
FastAPI, pycrdt and pywebview still need native bindings or compatible compiled
implementations. They remain explicit unresolved imports in build metadata;
executing an unavailable import raises ModuleNotFoundError. The
[recorded integration results](../benchmarks/discribe-26.9-compatibility.json)
include source hashes, CLI output, core-workflow parity and the remaining Nitrogen
runtime error. Nothing silently
falls back to CPython or replaces an application function with a stub.

## Native asynchronous execution

Async functions create suspended heap frames. Calls do not run their bodies;
`await` resumes them through a cooperative native task scheduler. Captures, local
values and active exception state remain traced across suspension. Async context
managers await both entry and exit, including return/error/cancellation cleanup.

Selected `asyncio` APIs now execute in CaRT: `run`, `sleep`, `create_task`,
`gather` (including `return_exceptions`), `wait_for`, cancellation and FIFO locks.
Task cancel/done/result/exception methods are available. Timeouts cancel and drain
the child so its cleanup executes. Completed tasks are removed from the scheduler's
root list, and zero-delay scheduling does not insert a fixed sleep. General
Future/transport/socket integration, async iteration/generators, arbitrary custom
awaitables, manual coroutine driving and the complete asyncio API remain open.

`contextlib.suppress` and synchronous `nullcontext` have native implementations.
Exception groups and the full contextlib API remain unsupported.

## CLI and HTTP

`sys.argv` receives actual executable arguments; `sys.exit` preserves exit status.
Native argparse supports selected ArgumentParser/add_argument options, positional
and named arguments, typed conversion, defaults/choices/required arguments,
store/store_true/store_false/count actions, `?`/`*`/`+`/integer nargs,
`parse_args`, `parse_intermixed_args`, help and parser errors. Parsing options are a
bounded subset; custom formatters, subparsers and complete diagnostic formatting
are not implemented. Unimplemented options are rejected explicitly.

`HTTPServer` and `ThreadingHTTPServer` serve static files with the native
`SimpleHTTPRequestHandler`, optionally wrapped in `partial(directory=...)`.
GET/HEAD, content lengths/types, index.html, redirects and missing-file errors are
supported. Threaded requests use POSIX worker threads that operate on C-owned
request data, without calling the single-threaded CaRT heap. A slow connection
therefore does not block other requests. Custom Python handlers, directory
listings, TLS and complete http.server emulation remain unsupported.

Server APIs include serve_forever, handle_request, server_close, shutdown,
timeout and address attributes. Foreground serving translates SIGINT into the
native KeyboardInterrupt path, allowing Discribe's finally block to close it.
HTTP builds record POSIX thread compile/link flags in their manifests.

## Other application operations

- Arbitrary-precision integer OR/AND/XOR, inversion and left/right shifts preserve
  negative-number semantics; negative shift counts raise ValueError.
- Session persistence helpers: `os.open` and common flag constants, Path.glob,
  Path.with_suffix, Path.unlink(missing_ok=...), dict.pop and secrets.compare_digest.
- Native container printing now uses repr for contained exceptions and objects.
- CaRT ABI **4**, a separate object-cache namespace, and updated wheel/runtime
  metadata account for coroutine state and process arguments.

The tests compare native O0/O3 behavior with CPython, exercise real concurrent
HTTP requests, and check suspended-frame/cyclic-object cleanup using GCC and
Clang ASan/UBSan. No universal application speedup is claimed.
